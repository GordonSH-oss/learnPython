# 02 类型、变量与运算

## 学习目标

完成本章后，你应能：

- 区分基础类型、派生类型和用户定义类型。
- 根据数据含义选择整数、浮点数、布尔值和字符类型。
- 使用 `sizeof`、`<limits.h>` 和 `<stdint.h>`，避免假定类型的具体大小。
- 使用 `const` 表达只读意图，并区分“指向只读对象的指针”和“不能改向的指针”。
- 预测整数除法、整数提升、常用算术转换和显式转换的结果。
- 识别有符号溢出、无符号回绕、符号混用和格式说明符不匹配等风险。
- 正确使用常见算术、比较、逻辑、赋值、条件和位运算符。

本章先建立类型与表达式的整体模型。数组、指针、函数类型、结构体、联合和枚举会在后续章节展开。

## 类型决定如何解释数据

C 中的对象是一块在生命周期内保存值的存储区域。类型决定编译器如何解释其中的数据，包括：

- 可能保存哪些值。
- 通常需要多少存储空间以及如何对齐。
- 可以执行哪些运算。
- 表达式求值和类型转换遵守哪些规则。

```c
int count = 3;
double price = 12.5;
double total = count * price;
```

`count * price` 并不是先进行整数乘法。计算前，`count` 会转换成 `double`，随后执行浮点乘法，结果也是 `double`。

类型不只影响单个变量，也影响整个表达式。阅读 C 代码时，可以依次问：每个操作数是什么类型、运算前发生什么转换、结果是什么类型。

## C 类型全景

C 的类型可以先按下面的层次理解：

| 类别 | 示例 | 本教程中的位置 |
| --- | --- | --- |
| 算术类型 | `_Bool`、字符类型、其他整数类型、浮点类型 | 本章 |
| `void` 类型 | 表示没有可直接使用的值 | 本章 |
| 派生类型 | 数组、指针、函数类型 | 第 04～06 章 |
| 用户定义类型 | 结构体、联合、枚举 | 第 07 章 |

数组不是像 `int` 那样的算术类型，而是从元素类型派生出的类型。例如，`int scores[3]` 的类型是“包含 3 个 `int` 元素的数组”。同理，`int *` 是指向 `int` 的指针类型，`double(double)` 可以描述接收并返回 `double` 的函数类型。

```c
int score = 90;                 // int
int scores[3] = {90, 85, 78};  // int 的数组
int *score_ptr = &score;        // 指向 int 的指针
```

这里只需先认出这些声明。第 05 章解释数组的连续存储和边界，第 06 章解释地址与指针。

### `void` 表示没有可直接使用的值

`void` 是一种不完整类型，常见用途有：

- `void log_message(void)`：函数不返回值，也不接收参数。
- `void *`：通用对象指针，第 06 章会介绍。

不能定义普通的 `void` 对象，因为编译器不知道它应占多少空间：

```c
// void value;  // 错误
```

## 整数类型

C 的整数类型不是只有 `int`。常用类型包括：

| 类型家族 | 常见写法 | 说明 |
| --- | --- | --- |
| 布尔 | `_Bool`、`bool` | 表示假或真 |
| 字符 | `char`、`signed char`、`unsigned char` | 字符或小整数；三者是不同类型 |
| 短整数 | `short`、`unsigned short` | 至少 16 位 |
| 整数 | `int`、`unsigned int` | 通常是默认整数类型 |
| 长整数 | `long`、`unsigned long` | 不小于 `int` |
| 更长整数 | `long long`、`unsigned long long` | 至少 64 位 |

`signed int` 可以简写为 `int`，`unsigned int` 可以简写为 `unsigned`。标准只规定类型之间的最小范围和大小关系，并不保证 `int` 永远是 32 位，也不保证 `long` 永远是 64 位。

```c
#include <limits.h>
#include <stdio.h>

printf("int: %d to %d\n", INT_MIN, INT_MAX);
printf("unsigned int max: %u\n", UINT_MAX);
```

如果接口要求精确宽度，可以使用 `<stdint.h>` 中实现提供的固定宽度类型，例如 `int32_t`、`uint32_t` 和 `uint64_t`。如果只关心“至少能表示这么大”，还可以考虑 `int_least32_t` 或 `int_fast32_t`。

不要因为某种类型名字更长就盲目选择它。一般原则是：普通计数和算术优先考虑 `int`；对象大小和数组长度通常使用 `size_t`；协议、文件格式和二进制接口需要明确宽度时使用 `<stdint.h>` 类型。

### 字符也是整数

字符常量 `'A'` 在 C 中具有 `int` 类型，字符对象通常使用 `char` 保存：

```c
char grade = 'A';
printf("%c: %d\n", grade, (unsigned char)grade);
```

普通 `char` 是否有符号由实现决定。处理任意原始字节时，优先使用 `unsigned char`；处理文本时使用 `char`，但不要假定一个 `char` 就对应一个完整的 Unicode 字符。C 字符串和文本编码将在第 05 章继续讨论。

### `_Bool` 与 `bool`

`_Bool` 是 C 的基础类型。包含 `<stdbool.h>` 后，可以使用更易读的 `bool`、`true` 和 `false`：

```c
#include <stdbool.h>

bool ready = true;
```

任何标量值转换为布尔值时，`0` 转换为假，非 `0` 转换为真。比较和逻辑运算的结果是整数值 `0` 或 `1`。

## 浮点类型

C 提供三种标准浮点类型：

- `float`
- `double`
- `long double`

浮点字面量 `1.5` 默认是 `double`；`1.5f` 是 `float`；`1.5L` 是 `long double`。

浮点数能表示很大的范围，但许多十进制小数不能被二进制浮点数精确表示：

```c
double sum = 0.1 + 0.2;
printf("%.17f\n", sum);
```

因此，不要默认用 `==` 比较计算得到的浮点结果。是否使用容差比较取决于数据尺度和误差要求。金额等必须满足精确十进制规则的数据，通常应使用整数最小单位或专门的十进制表示，而不是直接依赖 `double`。

## 声明、初始化与限定

声明把名称与类型关联起来，初始化为对象提供初始值：

```c
int attempts = 0;
double ratio = 0.0;
bool enabled = false;
```

自动存储期的局部变量如果没有初始化，其值是不确定的；读取它可能产生未定义行为：

```c
int count;
// printf("%d\n", count);  // 错误：count 尚未初始化
```

尽量在获得有意义的初值时声明变量，并让作用域保持紧凑。

### `const` 表达只读访问

`const` 是类型限定符。用 `const` 限定对象后，程序不能通过这个对象名称给它赋新值：

```c
const double tax_rate = 0.13;
// tax_rate = 0.15;  // 错误：不能修改 const 对象
```

`const` 同时向读者和编译器表达“这里只应读取”。它可以阻止意外赋值，但不负责以下事情：

- 它不会自动把变量变成 C 的整数常量表达式。例如，在标准 C 中，块作用域的 `const int length = 10` 不能用于所有要求编译期整数常量的场合。
- 它不保证对象一定存放在物理只读内存中。
- 它不表示对象在整个程序中绝对不会变化；同一对象可能还存在其他具有写权限的访问方式。

初始化 `const` 对象尤其重要，因为初始化完成后不能再通过该名称赋值：

```c
const int retry_limit = 3;  // 声明时提供有效值
```

不要通过去掉 `const` 的强制转换尝试修改真正定义为 `const` 的对象，这样做会产生未定义行为：

```c
const int limit = 3;
int *limit_ptr = (int *)&limit;
// *limit_ptr = 5;  // 未定义行为
```

### `const` 与指针

`const` 和指针组合时，必须分清被限制的是“指针所指的对象”还是“指针本身”：

| 声明 | 指针能否改指向 | 能否通过指针修改所指对象 |
| --- | --- | --- |
| `const int *p` | 可以 | 不可以 |
| `int *const p = &value` | 不可以 | 可以 |
| `const int *const p = &value` | 不可以 | 不可以 |

可以从变量名开始理解声明：

```c
int first = 10;
int second = 20;

const int *current = &first; // current 是指针，指向 const int
current = &second;           // 可以改变指针保存的地址
// *current = 30;            // 错误：不能通过 current 修改整数

int *const fixed = &first;   // fixed 是 const 指针，指向 int
*fixed = 30;                 // 可以修改 first
// fixed = &second;          // 错误：fixed 不能改指向
```

`const int *p` 限制的是“通过 `p` 进行的访问”，不一定表示底层对象本身不可修改：

```c
int score = 90;
const int *view = &score;

score = 95;  // 可以：score 本身不是 const
// *view = 95; // 错误：view 只提供只读访问
```

字符串字面量不允许修改，因此保存它的地址时通常使用 `const char *`：

```c
const char *name = "Alice";
name = "Bob";  // 可以让 name 指向另一个字符串
// name[0] = 'T'; // 错误：不能通过 name 修改字符
```

字符串和字符串字面量将在第 05 章展开，指针声明及其安全访问规则将在第 06 章展开。

### 用 `const` 说明函数参数的方向

函数不会修改指针所指的数据时，应把参数声明为指向 `const` 的指针。这既说明接口意图，也能让编译器阻止函数体中的误写：

```c
#include <stddef.h>
#include <string.h>

typedef struct {
    const char *key;
    int value;
} Entry;

int lookup(const Entry entries[], size_t count,
           const char *key, int *result) {
    for (size_t i = 0; i < count; ++i) {
        if (strcmp(entries[i].key, key) == 0) {
            *result = entries[i].value;
            return 1;
        }
    }
    return 0;
}
```

这个函数的参数可以按输入和输出理解：

- `const Entry entries[]`：输入数组，函数只查询元素。参数位置中的这种写法等价于 `const Entry *entries`。
- `const char *key`：输入字符串，函数只读取字符。
- `int *result`：输出参数，函数找到键后需要写入结果，因此不能把所指的 `int` 限定为 `const`。

这里的 `const` 只限制 `lookup` 通过这些参数执行的操作，不负责保证指针有效，也不管理对象生命周期。函数仍然需要遵守数组边界、空指针和对象生命周期等规则。

## `sizeof` 与对象大小

`sizeof` 返回类型或表达式结果类型占用的字节数，结果类型是无符号整数类型 `size_t`：

```c
printf("int: %zu bytes\n", sizeof(int));
printf("double: %zu bytes\n", sizeof(double));
```

C 中一个字节定义为 `sizeof(char)`，因此 `sizeof(char)`、`sizeof(signed char)` 和 `sizeof(unsigned char)` 都是 `1`。一个字节至少有 8 位，但不要求所有实现都恰好是 8 位；`CHAR_BIT` 定义在 `<limits.h>` 中。

对普通表达式使用 `sizeof` 时，表达式通常不会被求值：

```c
int value = 1;
size_t bytes = sizeof(value++);
// value 仍是 1；不要把副作用藏在 sizeof 中。
```

变长数组是一个需要单独考虑的例外。现阶段的实用规则是：不要在 `sizeof` 的操作数中写带副作用的表达式。

`sizeof` 给出存储大小，不等于数值范围，也不能告诉你对象当前保存了什么值。结构体还可能因为对齐而包含填充字节，第 07 章会继续解释。

## 表达式中的类型转换

转换可能由语言规则隐式发生，也可以由强制类型转换显式要求。显式转换只改变值的表示或编译器解释方式，不会自动验证结果是否符合业务要求。

### 整数除法

两个整数相除仍然执行整数除法，小数部分向零截断：

```c
int result = 5 / 2;          // 2
double wrong = 5 / 2;       // 先得到 2，再转换为 2.0
double right = 5.0 / 2;     // 2.5
double explicit = (double)5 / 2; // 2.5
```

目标变量是 `double` 并不会反过来改变右侧表达式的计算方式。转换必须在除法发生前介入。

对于负数，整数除法向零截断，余数与被除数同号或为零。例如，`-5 / 2` 是 `-2`，`-5 % 2` 是 `-1`。

### 整数提升与常用算术转换

许多运算不会直接使用比 `int` 更窄的整数类型。`char`、`signed char`、`unsigned char`、`short` 和 `_Bool` 通常先进行整数提升，再参与计算：

```c
unsigned char a = 200;
unsigned char b = 100;
int sum = a + b;  // 常见实现中先提升为 int，结果是 300
```

不同类型混合运算时，编译器会寻找一个共同类型。常见直觉是整数会向范围更大的整数类型转换，整数与浮点数混合时整数会转换为相应浮点类型。但有符号与无符号整数混用的规则更容易产生反直觉结果：

```c
int balance = -1;
unsigned int limit = 1;

if (balance < limit) {
    // 不要假定这里一定执行。
}
```

在常见实现中，比较前 `balance` 会转换为很大的 `unsigned int`，条件因此为假。编译器警告可以帮助发现此类混用；更好的做法是让表达同一概念的值使用兼容类型，并在转换前检查范围。

### 赋值与显式转换

赋值时，右侧值会转换为左侧类型。窄化转换可能丢失信息：

```c
double temperature = 23.9;
int rounded = (int)temperature;  // 23，不是四舍五入
```

浮点数转换为整数时会向零截断。如果截断后的值超出目标整数类型的可表示范围，行为未定义。需要四舍五入时，应根据规则使用 `<math.h>` 中的相应函数，并在转换前确认范围。

强制转换不应只是为了压掉警告。每次显式转换都应能回答：为什么信息不会丢失，或者为什么丢失是有意且可接受的。

## 溢出与回绕

整数运算的风险取决于有符号性：

- 有符号整数运算结果超出类型范围属于未定义行为。
- 无符号整数按模 `2^N` 运算，会发生定义明确的回绕。

```c
unsigned int value = 0;
value -= 1;  // 回绕为 UINT_MAX
```

无符号回绕虽然有定义，但不代表符合业务意图。长度相减、倒序循环和容量计算都可能因此出错。

在执行可能溢出的运算前检查边界。例如，判断两个正的 `size_t` 能否相加：

```c
#include <stdint.h>

if (right > SIZE_MAX - left) {
    // left + right 会溢出
}
```

不要先计算再检查，因为溢出可能已经发生。编译器优化会假定有符号溢出永远不会发生，不能把观察到的机器回绕当作语言保证。

## 常用运算符

### 算术与一元运算符

- 算术：`+ - * / %`
- 正负号：`+value`、`-value`
- 自增与自减：`++ --`

`%` 只用于整数。前置 `++i` 先修改再产生新值，后置 `i++` 产生旧值后再修改。在值不需要参与更大表达式时，单独写成一条语句最清楚：

```c
count++;
```

避免在一个表达式中多次修改同一对象，也不要依赖难以判断的求值顺序：

```c
// int result = i++ + i++;  // 未定义行为
```

### 比较与逻辑运算符

- 比较：`== != < <= > >=`
- 逻辑：`&& || !`

不要把比较 `==` 误写成赋值 `=`。开启编译警告可以帮助发现可疑条件。

`&&` 和 `||` 从左到右求值并具有短路行为：结果由左侧确定时，右侧不会执行。这常用于先验证条件，再进行只有验证成功才安全的操作：

```c
if (count != 0 && total / count > 10.0) {
    // count 为 0 时不会执行除法
}
```

### 赋值与复合赋值

- 简单赋值：`=`
- 复合赋值：`+= -= *= /= %= &= |= ^= <<= >>=`

`value += amount` 大致表达 `value = value + amount`，但左侧只求值一次，并且最终结果仍会转换回 `value` 的类型。复合赋值不能消除窄化或溢出风险。

### 条件运算符

条件运算符根据条件选择两个表达式之一：

```c
const char *label = score >= 60 ? "pass" : "fail";
```

它适合简短的值选择。存在多步操作或副作用时，使用 `if` 通常更容易阅读。

### 位运算符

- 按位与、或、异或：`& | ^`
- 按位取反：`~`
- 左移、右移：`<< >>`

位运算常用于标志位、掩码、协议字段和底层接口，通常优先对无符号整数使用：

```c
unsigned int flags = 0;
flags |= 1u << 2;        // 设置第 2 位
bool enabled = (flags & (1u << 2)) != 0;
```

不要混淆按位运算 `& |` 与逻辑运算 `&& ||`。移位还受到位宽、移位次数和操作数值的约束；第 13 章会系统讨论位操作。

### 优先级与括号

运算符优先级决定表达式如何分组，但不能保证各部分按你看到的顺序求值。例如，乘法优先于加法，所以 `a + b * c` 等价于 `a + (b * c)`。

不要靠背完整优先级表来编写复杂表达式。混合算术、比较、逻辑或位运算时，使用括号表达意图，并把有副作用的步骤拆成独立语句。

## 输入、输出与格式说明符

可变参数函数 `printf` 不知道每个参数的真实类型，必须依赖格式说明符正确解释参数。类型不匹配会产生未定义行为。

| 值的类型 | `printf` | `scanf` |
| --- | --- | --- |
| `int` | `%d` | `%d` 与 `int *` |
| `unsigned int` | `%u` | `%u` 与 `unsigned int *` |
| `long` | `%ld` | `%ld` 与 `long *` |
| `long long` | `%lld` | `%lld` 与 `long long *` |
| `size_t` | `%zu` | `%zu` 与 `size_t *` |
| `double` | `%f` | `%lf` 与 `double *` |
| `long double` | `%Lf` | `%Lf` 与 `long double *` |
| 字符 | `%c` | `%c` 与 `char *` |
| C 字符串 | `%s` | 不建议无宽度限制地读取 |

`printf` 中的 `float` 参数会提升为 `double`，所以使用 `%f`；`scanf` 接收的是目标对象地址，`float *` 和 `double *` 不同，因此分别使用 `%f` 和 `%lf`。

读取输入时必须检查返回值：

```c
double value;
if (scanf("%lf", &value) != 1) {
    fprintf(stderr, "输入不是有效数字\n");
    return 1;
}
```

`&value` 取得变量地址，第 06 章会解释其完整含义。现实程序读取一整行后再解析通常更容易处理错误和残余输入，第 05 章和第 09 章会继续讨论字符串及错误处理。

固定宽度整数的可移植格式说明符定义在 `<inttypes.h>` 中。例如打印 `int64_t` 时使用 `PRId64`，不要假定它一定对应 `long` 或 `long long`。

## 阅读表达式的检查方法

遇到不确定的表达式时，按以下顺序分析：

1. 写出每个操作数的类型，而不只是它当前的值。
2. 判断是否发生整数提升或常用算术转换。
3. 确定真正执行运算时采用的类型。
4. 判断结果是否可能超出该类型的范围。
5. 判断赋值、返回或传参时是否还会发生一次转换。

例如：

```c
int count = 3;
int total = 10;
double average = total / count;
```

两个操作数都是 `int`，因此先得到整数结果 `3`，再转换为 `double`，最终 `average` 是 `3.0`。正确写法可以是 `(double)total / count`。

## 常见错误

### 把目标类型当成运算类型

```c
double ratio = 1 / 2;  // 0.0，不是 0.5
```

### 混用有符号和无符号整数

负数转换为无符号类型后会成为很大的值，比较结果可能与直觉相反。统一概念对应的类型，并认真处理编译器警告。

### 依赖类型的固定大小

不要把 `sizeof(long) == 8` 当作可移植前提。需要精确宽度时使用 `<stdint.h>`，需要对象大小时使用 `sizeof`。

### 使用错误的格式说明符

`printf("%d", sizeof value)` 是错误的，因为 `sizeof` 返回 `size_t`；应使用 `%zu`。

### 通过强制转换隐藏问题

转换不能修复无效范围、错误地址或不兼容的数据含义。先证明转换正确，再写转换。

## 检查点

在运行代码前，先预测下面各表达式的结果和类型：

```c
5 / 2
5 / 2.0
(double)(5 / 2)
(double)5 / 2
3 < 4
0 || 7
```

答案分别是：整数 `2`、`double` 类型的 `2.5`、`double` 类型的 `2.0`、`double` 类型的 `2.5`、整数 `1`、整数 `1`。重点不是记住答案，而是能解释转换发生在运算之前还是之后。

## 与 Python/C API 的联系

Python 整数可以按需扩展精度，而 C 整数具有固定类型范围；把 `PyLong` 转换为 C 整数时必须检查溢出和 Python 异常状态。`size_t`、`Py_ssize_t` 和固定宽度整数也表达不同语义，不能只因为机器上大小相同就互换。后续编写扩展时，本章的类型转换、范围检查和格式说明符规则仍然适用。
