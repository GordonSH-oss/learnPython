# 12 调试、测试与安全

## 学习目标

完成本章后，你应该能够：

- 从编译警告、测试、sanitizer 和调试器获得不同层次的反馈
- 把故障缩小到可重复的最小输入和失败边界
- 为正常值、边界值、无效输入和资源失败设计测试
- 理解未定义行为为什么不能用一次运行结果解释

## 质量反馈阶梯

1. 编译器警告：发现类型、格式和控制流问题。
2. 单元测试：快速验证一个函数的输入输出契约。
3. 集成测试：验证模块、文件、进程或网络边界。
4. AddressSanitizer：发现越界、释放后使用和重复释放。
5. UndefinedBehaviorSanitizer：发现部分算术、移位和对齐错误。
6. ThreadSanitizer：发现数据竞争，平台和其他 sanitizer 组合受限。
7. 调试器：在具体执行点检查线程、调用栈、变量和内存。

工具各自只能观察一部分问题。测试通过不证明没有未覆盖的输入，sanitizer 没报告也不证明所有权设计正确。

## 当前项目命令

```bash
make examples
make test
make sanitize
```

`make test` 应完整返回状态 `0`。只看到部分“passed”输出不代表后续步骤没有失败。测试脚本也属于产品代码，需要正确设置工作目录、清理临时文件并传播子命令错误。

当前 Makefile 不把 `CFLAGS` 内容记录为目标依赖。执行 `make sanitize` 后若切回普通构建，应先运行 `make clean`；更大型的项目通常为 debug、release 和 sanitizer 使用独立构建目录，避免混用不同编译选项生成的 `.o`。

## 从失败现象到根因

使用固定流程：

```text
复现 -> 缩小输入 -> 定位首个错误状态 -> 修复根因 -> 添加回归测试
```

不要只在最终崩溃位置打补丁。越界写可能很早破坏内存，却在后续完全无关的 `free` 中才崩溃。

记录复现条件：编译器版本、优化级别、输入、操作系统、退出状态和 sanitizer 输出。未定义行为尤其可能随 `-O0`、`-O2` 或工具链变化。

## 使用 LLDB

```bash
lldb build/examples/06_pointers
(lldb) breakpoint set --name main
(lldb) run
(lldb) next
(lldb) step
(lldb) frame variable
(lldb) thread backtrace
(lldb) memory read ADDRESS
```

- `next` 执行当前行但不进入普通函数调用。
- `step` 进入函数。
- `thread backtrace` 展示当前线程调用路径。
- 崩溃后先查看最上层栈帧，再追溯输入和对象生命周期。

## 使用 sanitizer

```bash
clang -std=c17 -Wall -Wextra -Wpedantic -g \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  example.c -o /tmp/example
/tmp/example
```

阅读报告时关注：

1. 错误类别，例如 heap-use-after-free。
2. 第一次非法访问的源码位置。
3. 对象在哪里分配、在哪里释放。
4. 访问大小和目标区域边界。

LeakSanitizer 的可用性和默认行为因平台而异。需要检测泄漏时，应确认当前工具链是否实际启用，而不是只根据退出状态推断。

## 未定义行为

数组越界、无效指针解引用、有符号整数溢出、数据竞争和格式参数不匹配等行为不受 C 标准约束。优化器可以假定它们不会发生，因此程序可能崩溃、看似正常或产生无法按机器指令直觉解释的结果。

不能把“在我的机器上输出某值”写成未定义行为的教程结论。正确做法是识别违反了哪条语言或 API 前置条件。

## 测试设计

每个接口至少考虑：

- 正常输入
- 空值、零长度和最小值
- 最大合法边界
- 第一个非法边界
- 格式错误或外部资源失败
- 部分成功和清理路径

对于动态内存，可以通过把分配器包装成可注入接口模拟第 N 次分配失败；对于文件，可以使用临时目录和只读路径；对于网络，应优先使用本地测试服务器而不是公网。

`assert` 适合验证程序员必须保证的不变量，不适合处理用户可以触发的普通错误。定义 `NDEBUG` 后标准 `assert` 会被移除，因此不要在断言表达式里放必要副作用。

## 安全清单

- 所有输入都有长度、范围或格式约束。
- 每次数组访问都能证明索引有效。
- 大小加法和乘法在分配前检查溢出。
- 每次资源获取都有唯一释放责任和失败回滚。
- I/O 处理 EOF、错误和部分完成。
- `printf` 格式与参数类型严格匹配。
- 并发共享状态存在明确同步协议。
- 编译零警告，测试与适用的 sanitizer 全部通过。

## 动手练习

1. 给一个数组越界程序分别用 `-O0` 和 `-O2` 编译，说明为什么输出不是可靠契约。
2. 用 AddressSanitizer 定位一次释放后使用，并根据分配/释放栈解释根因。
3. 给动态数组增加分配失败测试，确认失败后旧状态仍然有效。
4. 故意让一个测试脚本中的子命令失败，验证整个测试命令能返回非零状态。
