# 12 调试、测试与安全

## 学习目标

使用警告、断言、调试器和 sanitizer 定位问题，理解未定义行为为什么危险。

## 质量反馈顺序

1. 编译器警告：最便宜的反馈，保持零警告。
2. 自动测试：验证已知输入、边界和失败场景。
3. AddressSanitizer：发现越界、释放后使用等内存错误。
4. UndefinedBehaviorSanitizer：发现有符号溢出、非法移位等问题。
5. 调试器：在断点处检查调用栈和变量。

运行：

```bash
make test
make sanitize
```

使用 LLDB：

```bash
lldb build/examples/06_pointers
(lldb) breakpoint set --name main
(lldb) run
(lldb) next
(lldb) frame variable
```

## 未定义行为

数组越界、解引用无效指针、读取未初始化变量、有符号整数溢出、格式参数不匹配等行为不受 C 标准约束。它不是“固定报错”，优化器可以假设它永远不会发生，因此结果可能随编译选项变化。

## 测试设计

每个函数至少考虑正常值、边界值、无效输入和资源失败。断言适合验证程序员必须保证的不变量，不适合处理用户可以触发的普通错误。

## 安全清单

- 所有输入都有长度或范围限制。
- 所有数组访问都能证明索引在范围内。
- 每次分配都检查失败，并有唯一释放责任。
- 指针为空、悬空或越界前不会被解引用。
- 所有 I/O 和转换函数返回值都被检查。
- `printf` 格式与参数类型严格匹配。
- 编译保持零警告，测试和 sanitizer 通过。
