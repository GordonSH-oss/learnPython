# 06 正确测量和优化

## 学习目标

建立包含正确性、热身、重复测量、数据转换、现实输入和端到端收益的基准方法，并正确解释加速比。

## 运行基准

```bash
make benchmark
```

`benchmark.py` 包含两组比较：

1. Python、ctypes 和 Python/C API 的同一平方和循环。
2. Python double 循环、ctypes 复制、ctypes buffer 和 C API buffer。

每组都先验证结果，再热身一次，重复计时并报告中位数。数字取决于 CPU、解释器、编译参数和系统负载，不能写成普遍结论。

## 基准首先是正确性实验

优化版本必须与参考实现共享：

- 输入定义域
- 输出和浮点容差
- 溢出语义
- 异常类型
- 对输入的修改规则

如果 Python 使用任意精度整数，而 C 版本在 `int64_t` 回绕，二者不是等价实现，不能只比较时间。

## 测量范围

至少区分：

```text
导入/动态加载
参数验证
数据转换或复制
跨语言调用
C 热点计算
结果对象创建
```

长运行服务通常更关心稳态调用；短命令行工具可能必须把 import 和动态链接时间也计入端到端延迟。

`ctypes copy` 把 iterable 转成 list 和 C 数组，这属于真实接口成本；`ctypes buffer` 借用已有 `array('d')`，输入契约更窄。两者不能只比较 C 循环而隐藏准备成本。

## 热身、重复和进程隔离

首次调用可能包含动态符号解析、缓存填充或内存分配。简单基准先热身，再重复运行并使用中位数。

更严谨的结果应使用 `pyperf`：

```bash
python -m pip install pyperf
python -m pyperf timeit --rigorous \
  -s 'from ctypes_demo import sum_squares' \
  'sum_squares(1_000_000)'
```

`pyperf` 可以使用子进程、校准循环次数并记录系统信息。发布性能数字时应保存命令、机器、Python 版本、编译器和输入规模。

## GC、CPU 和噪声

`timeit` 默认在计时期间关闭 cyclic GC，而手写计时不会。是否关闭 GC 应由真实工作负载决定并在报告中说明。

测量还会受以下因素影响：

- CPU 频率和温度
- 后台进程与调度
- debug、release、sanitizer 构建差异
- 内存分配器状态
- 缓存和 NUMA

不要用 sanitizer 构建报告生产性能。

## 边界粒度

假设跨边界一次成本为 `B`，每个元素 C 计算成本为 `C`：

```text
逐元素调用：N * (B + C)
批量调用：  B + N * C
```

因此应把整段扫描、解析或数组计算交给一次 C 调用。若算法仍需每个元素回调 Python，通常会重新引入高额边界成本。

## 算法优先

平方和公式比逐项循环复杂度更低。若生产需求允许，应先选择更好的算法，再决定实现语言。

报告应把两类收益分开：

- 算法收益：O(n) 改为 O(1)
- 实现收益：相同算法从 Python 循环迁移到 C

否则“C 快多少”没有可解释性。

## Amdahl 定律

若热点占总时间 40%，即使热点变为零成本，整体最大加速为：

```text
1 / (1 - 0.4) = 1.67x
```

微基准快 50 倍不代表请求延迟也快 50 倍。优化后应重新 profile，热点可能转移到数据复制、锁或 I/O。

## 内存和吞吐

速度不是唯一指标。还应测量：

- 峰值 RSS
- 临时对象和复制量
- 多线程吞吐与尾延迟
- GIL 竞争或 C mutex 竞争
- 输入变大后的缓存和内存带宽限制

零拷贝接口可能降低内存，却增加调用者保持对象存活的时间。优化决策需要同时考虑资源占用和接口复杂度。

## 性能回归

普通 CI 环境噪声较大，不适合用非常窄的时间阈值直接判定失败。可以：

- 单独保存 benchmark 结果做趋势分析
- 设置足够宽的回归阈值
- 使用固定性能机器定期运行
- 先用功能测试保证正确性

## 优化检查表

1. profiler 证明热点真实存在。
2. Python 参考实现和边界测试通过。
3. 输入范围、异常和所有权明确。
4. 算法已经合理。
5. 跨边界粒度足够大。
6. 转换和复制包含在正确计时范围内。
7. 使用 release 构建、多次测量和现实数据。
8. 检查端到端收益、内存和并发影响。
9. 记录工具链与平台，避免过度概括。

## 动手练习

1. 把平方和 `LIMIT` 改为 `10`、`1_000` 和 `1_000_000`，找出边界成本主导的区间。
2. 比较 `ctypes copy` 与 `ctypes buffer`，解释差异来自调用还是数据准备。
3. 用平方和公式实现第四个版本，分别报告算法和实现收益。
4. 使用 `pyperf` 重跑一个基准并保存 metadata。
5. 测量 import 加首次调用与稳态调用，判断你的应用更关心哪一个。
