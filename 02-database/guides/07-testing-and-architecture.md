# 07 数据库测试与应用架构

## 学习目标

把业务规则、事务边界和持久化细节分开，并选择能发现真实问题的测试层级。

## 推荐边界

```text
API/CLI -> Service（业务用例和事务） -> Repository（查询意图） -> SQLAlchemy/驱动
```

Repository 应表达业务查询，例如 `get_active_user_by_email()`，而不是为每张表机械包装所有 CRUD。简单项目可以直接在服务层使用 Session，不必为了“分层”制造无价值抽象。

## 测试层级

- 单元测试：纯业务规则，不连接数据库。
- SQLite 集成测试：快速验证通用 SQL 和事务结构。
- 真实数据库集成测试：验证 PostgreSQL 类型、锁、隔离、JSONB、方言 SQL。
- 端到端测试：验证请求、事务和序列化共同工作。

不要默认 SQLite 与 PostgreSQL 完全等价。涉及并发、大小写、日期、JSON、约束或数据库专属功能时，测试应运行在生产同类数据库上，可使用容器创建临时实例。

## 测试隔离

常见方式：每个测试创建临时数据库；每个测试开启事务并回滚；每个测试重建 schema。选择取决于速度和真实性。

Fixture 应负责创建和关闭连接。测试必须能随机顺序运行，不能依赖前一个测试留下的数据。

本目录的 `tests/test_sqlite_examples.py` 验证标准库示例中的事务和约束行为。
