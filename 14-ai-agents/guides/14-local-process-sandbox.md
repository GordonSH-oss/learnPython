# 14 本机进程 Sandbox

## 学习目标

能够使用本机执行器运行受限的 Python 任务，理解临时工作区、显式环境、超时、输出上限和进程组清理的作用与局限。

## 要看的代码

- `agent_core/sandbox/local.py`
- `tests/test_sandbox_local.py`
- `examples/react_agent.py`

## 概念模型

`LocalProcessSandbox` 把 `PythonCode` 写入策略工作区下的临时目录，使用当前 Python 解释器和 `shell=False` 启动。输入文件按声明写入，目标路径必须保持在工作区内；进程看不到未显式传入的宿主环境变量。

它适合离线教学、受信任代码和低风险内部自动化，不是强安全边界。执行器降低误操作范围，却不能保证恶意代码无法利用宿主内核、文件权限或解释器漏洞。

## 执行路径

1. 检查请求类型和声明文件路径。
2. 创建工作区并写入源码、输入文件。
3. 构造最小环境，设置 `cwd`、管道和进程组。
4. 在 Unix 上尽可能设置 CPU、内存和进程数限制。
5. 按时间和输出预算收集结果，必要时终止整个进程组。
6. 将结果规范化为 `ExecutionResult`。

## 底层机制

超时后不能只杀父进程，否则子进程可能继续运行；执行器应终止进程组并等待回收。输出必须按字节限制，解码时使用 replacement，避免异常输出破坏控制流程。平台不支持的资源限制要出现在策略摘要中，不能假称已生效。

## 检查点与练习

运行一个成功的 `PythonCode`，再依次验证非零退出、超时、输出超限和工具异常。尝试读取策略工作区之外的文件、写入 `../escape.txt`、使用绝对路径和读取未传入的 secret，记录每种行为的结果。

## 常见错误与生产注意

- 让脚本通过 `shell=True` 或未经 allowlist 的命令执行。
- 继承完整 `os.environ`，把凭据带入不可信进程。
- 只设置父进程超时，不清理子进程组。
- 将临时目录误认为容器级隔离。
- 忽略 macOS、Windows 与 Linux 对 resource 限制的差异。
