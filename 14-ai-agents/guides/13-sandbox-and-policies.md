# 13 Sandbox 与策略边界

## 学习目标

能够为 Agent 工具画出执行边界，区分工具授权、sandbox 策略和操作系统隔离，并为每次执行选择最小权限。

## 要看的代码

- `agent_core/sandbox/types.py`
- `agent_core/sandbox/local.py`
- `tests/test_sandbox_policy.py`

## 概念模型

sandbox 接收结构化的 `PredefinedCommand` 或 `PythonCode`，再由策略决定工作目录、网络、环境变量、输出、时间和资源上限。模型文本只能成为待校验的参数，不能直接成为 shell 命令。

授权回答“能不能调用这个工具”，sandbox 回答“即使调用成功，进程最多能影响什么”。两层都必须存在：通过工具授权的动作仍可能读取不该读的文件，sandbox 也不能替代业务数据授权。

## 执行路径

1. 应用将模型动作解析为类型化请求。
2. 工具注册表校验名称、参数和调用权限。
3. 按租户和任务创建最小 `SandboxPolicy`。
4. 执行器使用参数列表启动进程，收集结构化结果。
5. 记录停止原因、策略摘要和 trace 关联，不记录完整代码或环境。

默认拒绝网络，环境变量采用显式 allowlist，工作目录和输入文件都必须在声明范围内。超时、输出上限和重复动作都应有确定的停止行为。

## 底层机制

`Sandbox` 是执行协议，`LocalProcessSandbox` 和 `DockerSandbox` 是不同的实现。策略对象不可变，便于审计和重放；结果对象固定包含 stdout、stderr、returncode、停止原因、耗时和策略摘要。

本机进程 sandbox 不是强安全边界。`resource` 限制、临时目录和进程组清理能降低误操作影响，但不能抵御内核漏洞、宿主权限错误或所有文件系统攻击。承载任意不可信代码时应使用额外的容器、microVM 或专用执行服务，并进行独立评估。

## 检查点与练习

为一个只读数据分析工具设计策略：允许固定 Python 入口、禁止网络、只挂载声明输入、限制输出为 64 KiB。测试恶意 `../` 路径、绝对路径和未声明命令都被拒绝，并检查失败原因可被调用方稳定处理。

## 常见错误与生产注意

- 把 sandbox 当成授权系统，忽略租户和数据权限。
- 通过字符串拼接生成命令或允许任意 shell。
- 把宿主环境变量、密钥和 Docker socket 传入执行环境。
- 把本机进程隔离描述成可运行任意不可信代码的强边界。
- 只看最终输出，不保存策略版本和停止原因。
