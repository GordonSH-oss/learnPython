# 07 规划、ReAct 与预算

## 学习目标

能够选择直接执行、ReAct 或 plan-and-execute，利用可观察的计划和状态调试长任务，而不依赖模型私有推理文本。

## 概念模型

- ReAct：每轮根据观察选择下一动作，适合路径短且环境变化快。
- Plan-and-execute：先生成结构化步骤，再逐步执行与重规划，适合长任务。
- Reflection：用独立检查标准发现缺失证据，不等于无限自我对话。

可记录的是简短行动理由、计划、证据和决策结果，不要求模型输出隐藏思维链。

## 执行路径

计划应是结构化任务列表，每项包含状态、依赖、预算和完成证据。执行器只运行 ready 项，失败后根据错误类别重试、替代、等待审批或终止。

运行 `python 14-ai-agents/examples/react_agent.py` 可以观察一个离线 ReAct 轨迹。示例只记录 `decision`、`observation` 和 `final` 等结构化事件，不要求模型输出或保存完整私有思维链。

## 底层机制

规划增加调用次数，也增加陈旧计划与循环风险。应限制总步骤、同类动作次数、token、费用和墙钟时间，并用动作签名检测无进展循环。

## 检查点与练习

让 ReAct 示例的第一次搜索返回错误，增加第二次模型响应来改写 query，确认错误作为 observation 返回，而不是直接让进程崩溃。然后把“研究 Python 3.14 新特性”拆为可验证步骤，为每步定义完成证据。

## 常见错误与生产注意

- 把模型生成的计划当作可信事实。
- 每次失败都重新规划，丢失已完成证据。
- 反思没有明确 rubric，只增加成本。
- 预算只计算 token，不计算工具和人工等待时间。
