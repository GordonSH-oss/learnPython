# 16 身份、数据与供应链

## 学习目标

能够把身份、租户、数据分类、凭据、依赖和事件响应纳入 Agent 的安全设计，而不是只关注 prompt injection。

## 概念模型

每个动作都应关联主体、租户、会话、任务和资源。身份决定谁请求，授权决定可访问什么，sandbox 限制执行影响，审计记录发生了什么。上下文、记忆、检索索引和工具结果都必须按数据边界处理。

供应链包含模型、prompt、工具定义、依赖包、容器镜像、知识文档和 MCP 服务。任何一项被替换或投毒，都可能把已授权的 Agent 变成越权入口。

## 执行路径

1. 将用户和服务身份映射为短期、最小权限凭据。
2. 为 tenant/session/task 分配独立的 memory 与工作区。
3. 对检索内容标记来源、版本、保留策略和敏感等级。
4. 固定依赖与镜像版本，验证来源并扫描变更。
5. trace 只记录可审计元数据，不记录 prompt、凭据或原始敏感数据。
6. 发生事件后吊销凭据、冻结高风险工具、按 trace 定位受影响任务并复盘。

## 底层机制

多租户隔离必须贯穿检索过滤、缓存键、checkpoint、文件路径和 trace 查询。仅在 UI 隐藏其他租户数据不构成隔离。凭据应短期化且按工具绑定，不能把一个全局 API key 复制到模型上下文或子进程环境。

## 检查点与练习

设计两个 tenant 的研究任务，证明它们的 memory、工作区和检索证据不能交叉。随后模拟发现某个工具镜像版本存在问题：从 trace 中找出执行器、策略版本和任务标识，列出冻结、轮换、重跑与通知步骤。

## 常见错误与生产注意

- 以 session id 替代真实租户边界。
- 将长期全权限凭据注入 prompt、日志或 sandbox 环境。
- 缓存键未包含租户、知识版本或授权范围。
- 只扫描 Python 依赖，不审查镜像、MCP 服务和知识来源。
- 事件发生后只能搜索自然语言日志，无法按策略和任务范围响应。
