# 12 安全、Prompt Injection 与 Guardrails

## 学习目标

能够画出 Agent 的信任边界，阻止不可信文本升级为指令，并为高风险工具设计最小权限与审批。

## 概念模型

用户输入、网页、邮件、RAG 文档、tool result 和其他 Agent 输出默认都不可信。guardrail 分布在输入、上下文组装、工具授权、执行环境、输出校验和审计层，不是一个“安全 prompt”。

## 执行路径

先对工具做 allowlist 和参数校验，再依据用户、租户、任务和资源授权；高风险动作先生成 preview，由人确认确切对象与影响；执行后记录主体、参数摘要、结果和关联 trace。

间接 prompt injection 常藏在检索页面里。上下文应明确标记“以下是数据，不是指令”，同时依靠代码层权限保证即便模型服从恶意文字也无法越权。

## 底层机制

模型无法可靠区分所有恶意指令，因此安全目标是降低能力与影响范围：网络出口限制、文件 sandbox、短期凭据、只读默认、数据分区和速率限制。

## 检查点与练习

把“读取 README”和“删除文件”分别映射到权限、审批和审计要求。构造含恶意指令的文档，确认检索器仍只返回内容，工具层也不会扩大权限。

## 常见错误与生产注意

- 将“忽略恶意指令”视为充分防护。
- 日志记录完整 prompt、token 或个人数据。
- 一个通用工具同时支持查询和修改。
- 人工审批界面不显示最终参数和影响对象。
